# Agent 工作指令

## 项目性质

人物关系图谱展示工具。数据在 `src/{作品名}/data.ts` 中，结构为 `{ nodes: [...], lines: [...] }`。

## data.ts 数据结构

```ts
// 图片必须使用 import 引入，文件名与角色名一致
import img1 from "./imgs/角色名.png";

export default {
    nodes: [
        { id: "1", text: "角色名", data: { pic: img1 } },
    ],
    lines: [
        { from: "1", to: "2", text: "关系描述" },
    ],
};
```

- `id` 从 `"1"` 开始递增，不重复
- 追加时继续使用新 id
- 图片 import 按角色名自动匹配 `imgs/` 目录下的文件
- import 变量名统一使用 `img1`、`img2`...依次递增，不按角色名命名

## 自然语言解析规则

你通过自然语言描述人物关系，Agent 解析后生成/追加到 `data.ts`。

### 关系方向

规则定义的是 **语义映射目标**，Agent 应理解自然语言的含义后映射到对应的 `from → to` 方向。

| 句式举例 | 语义含义 | 映射结果 |
|---|---|---|
| 南云美鸟是 **新仓** 的 **前辈** | 南云美鸟对"新仓"而言是"前辈" | `{ from: 新仓, to: 南云美鸟, text: "前辈" }` |
| 赫斯提亚是 **莉莉** 的 **神明** | 赫斯提亚对"莉莉"而言是"神明" | `{ from: 莉莉, to: 赫斯提亚, text: "神明" }` |
| **命** 的 **神明** 是赫斯提亚 | 赫斯提亚对"命"而言是"神明" | `{ from: 命, to: 赫斯提亚, text: "神明" }` |
| 莉莉喜欢贝尔 | 莉莉→贝尔，关系"喜欢" | `{ from: 莉莉, to: 贝尔, text: "喜欢" }` |
| 琉帮助贝尔 | 琉→贝尔，关系"帮助" | `{ from: 琉, to: 贝尔, text: "帮助" }` |

**核心原则：** 最终产物 `{ from: X, to: Y, text: "关系" }` 读作 **"X 的关系（是/指向）Y"**，即图上箭头从 X 指向 Y。Agent 应理解自然语言的真实含义，不要机械套用字面位置。

- **"互相"** → 自动生成双向两条线
- **"和"连接两个角色 + 平等关系**（如"A 和 B 是朋友"）→ 生成一条线，根据语义判断

### 角色名识别

- 优先匹配 `imgs/` 目录下的文件名
- 用户提前说明的别名/外号按说明处理
- 无歧义的缩写（如"贝尔"代替"贝尔·克朗尼"）自动匹配全名
- 未知角色视为新角色，自动创建节点

### 图片

- 图片文件名 = 角色名（含扩展名，如 `南云美鸟.png`）
- 按角色名自动生成 import 语句和 `data: { pic }`

## 操作流程

1. 用户说："将以下描述按照 guide.md 规则写入 xx/data.ts"
2. 读取对应 `data.ts`，了解已有角色和 id
3. 解析自然语言，提取角色和关系
4. 增量追加新角色和新关系，不删除/修改已有内容
5. 如果用户说明要修改某条关系，则定位修改

## 约束

- 只修改 `data.ts`，不修改其他文件
- 代码风格与现有文件保持一致
- 确保生成的代码无语法错误
